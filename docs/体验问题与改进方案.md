# 体验问题与改进方案

2026-11-07，针对 v0.1.0。

> **决定（同日）**：保留B站原本的语义，不解析歌名和歌手，不接 LRCLIB；不找 MyGo 原作者改 App，App 定死的叫法就接受。v0.2.0 只做：排行换成新分区接口、音乐榜按视频原样显示、统一 ID、「歌单」搜索标签在自己的收藏夹里找、增加网页登录方式。下文第二、三节里关于解析和歌词的部分只作为当时的分析保留。

## 结论

B站和 MyGo Music 确实对不上，但不是没法用：B站的基本单位是「视频」，MyGo 的是「歌」。v0.1.0 基本是把视频原样当歌塞进去，所以哪儿都有点别扭。

改进的思路是让插件做一层「翻译」：能拿到真实歌曲信息的地方（音乐榜、标题里的《歌名》、歌词库）尽量还原成歌；拿不到的地方老实按视频处理，但不要假装它是歌。

下面先核实你说的两个问题，再列我想到的其他问题，最后按优先级排序。

---

## 一、分区排行是旧的：核实属实，而且是我用错了接口

实测（2026-11-07）：

| 接口 | 状态 |
| --- | --- |
| `ranking/region`（v0.1.0 用的，旧分区 rid=3、28、31…） | **冻结了**。所有分区里最新的视频都是约 580 天前（2025 年 4 月前后）的，正好是 B站改用新分区体系的时候 |
| `ranking/v2?rid=3`（旧分区号） | 同样冻结，最新的也是 583 天前 |
| `ranking/v2?rid=1003`（新分区「音乐」） | **正常**。100 条，最新的是当天，中位数 3 天前 |
| `ranking/v2?rid=2016` 等新的子分区 | 返回 -400 或 -352，不能按子分区查 |
| `region/feed/rcmd?from_region=1003` | **正常**。音乐分区的推荐流，可以翻页，前后两页不重复 |
| B站音乐榜 `toplist/music_list` | **正常**。周榜，第 230 期当天刚出 |

所以不是 B站冷落分区导致没数据，而是旧分区号对应的接口不再更新了。

**怎么改**：
- 「音乐区热门」改用 `ranking/v2?rid=1003`。
- 「分区排行」那组链接整个去掉，因为新分区拿不到子分区排行。换成「音乐区新鲜推荐」，用 `region/feed/rcmd`，每次打开都不一样。
- 「B站音乐榜」保留，它本来就是新的。

还有一个顺带发现的 bug：音乐榜其实给了**结构化的歌曲信息**，`music_title` 是歌名、`singer` 是歌手、`album` 是专辑。我代码里读的是一个不存在的字段 `song_name`，于是退回成了视频标题。修好之后，榜单显示的就是「雨爱 — 杨丞琳」，而不是「这才是《雨爱司凤版》原版MV，邦吧邦吧邦吧【AI MV大赛】」。

## 二、语义错位

| MyGo 的概念 | v0.1.0 的对应 | 问题 | 建议 |
| --- | --- | --- | --- |
| 歌曲 | 视频（或分P） | 名字是视频标题，满是【Hi-Res无损】、｜、‘歌词摘句’ | **从标题里解析歌名**，原标题放到专辑名里，见下文 |
| 歌手 | UP 主 | 「VV音乐局」不是《晴天》的歌手 | 歌曲的「歌手」改成解析出的歌手；UP 主挪到「专辑艺人」上 |
| 专辑 | 视频本身（分P列表 / 所属合集） | 这个对应其实挺合理 | 保留，专辑页的艺人是 UP 主 |
| 歌单 | 收藏夹 | 收藏夹里什么都有：游戏、教程、美食 | 插件判断不了视频是不是音乐（收藏夹接口不返回分区）。照常显示，再加一个设置让用户指定当「喜欢」的收藏夹 |
| 喜欢（❤） | 加入默认收藏夹 | 默认收藏夹通常最杂；B站自己的「点赞」又是另一回事 | 加设置「当作喜欢的收藏夹」，默认是默认收藏夹，用户可以填「音乐」之类的名字 |
| 关注歌手 | 关注 UP 主 | 解析出来的歌手不是 B站账号，关注不了 | 只有 UP 主可以关注，歌手页不提供关注 |

### 歌名、歌手怎么解析

音乐区标题有几种很常见的写法：

| 原标题 | 解析结果 |
| --- | --- |
| 【𝐇𝐢-𝐑𝐞𝐬无损音质】｜《晴天》- 周杰伦 -‘故事的小黄花’ | 歌名 晴天，歌手 周杰伦 |
| 周杰伦《晴天》官方MV | 歌名 晴天，歌手 周杰伦 |
| 【4K】晴天 - 周杰伦 | 歌名 晴天，歌手 周杰伦（「A - B」的顺序有歧义，见下） |
| 《十年》但是小猫改编版 | 歌名 十年，歌手无法判断，用 UP 主 |

规则：
1. 去掉【…】、[…] 里的修饰标签，比如 Hi-Res、无损、4K、MV、中字、官方。
2. 有《》就以书名号里的内容为歌名，书名号紧挨着的前后文本当歌手候选。
3. 没有《》时，「A - B」只在一边能和 UP 主名、搜索关键词或已知歌手对上时才拆，否则保持原样。
4. **解析不出来就不硬猜**：歌名用清理过标签的标题，歌手用 UP 主。错的歌手比 UP 主更糟糕。

歌手要能点进去，所以给它一个特殊 ID，比如 `singer:周杰伦`。点进去的歌手页 = 在音乐分区里搜这个名字、按播放量排的视频，UP 主页保持现在的样子。

这套规则是启发式的，保守估计能覆盖音乐区七八成的标题，剩下的照旧显示。

## 三、我想到的其他问题

1. **同一首歌有两个 ID**（已经能复现的 bug）。搜索结果里是 `BV…`，历史记录和推荐里是 `BV…|cid`。同一个视频在「喜欢」、播放队列、App 的播放记录里会被当成两首。改法：单P视频和第 1P 一律用 `BV…`，只有第 2P 及以后才带 cid。
2. **搜索结果很杂**：教学、reaction、鬼畜、游戏剪辑。改法：搜索默认只搜音乐分区，结果太少时再退回全站。教学、教程、伴奏、reaction 这类往后排，但不删。
3. **首页「为你推荐」不是音乐**：B站的个性化推荐是全站的，会推游戏和美食。改法：登录后只保留音乐分区的条目，凑不够就补「音乐区新鲜推荐」。「首页推荐」电台同样处理。
4. **歌词几乎没有**：B站字幕要登录才拿得到，音乐视频大多也没有；AI 字幕是听写，错字多。改法：解析出歌名和歌手后，去 [LRCLIB](https://lrclib.net)（免费、开放的歌词库）查**带时间轴**的歌词，按时长匹配，误差 2 秒以内才用，这样能避开 live 版、剪辑版对不上的问题。实测《晴天》周杰伦 270 秒能查到逐行歌词。视频自带字幕的仍然优先。要给插件加 `lrclib.net` 的网络权限，更新时 App 会再问用户一次。
5. **长视频和串烧**：一小时的歌单合集、演唱会全程会被当成一首「歌」。改法：超过 20 分钟的视频在曲名后标上时长，比如「（1:02:13 合集）」。如果 UP 主在简介里写了时间轴，理论上能切成多首，但这条先不做。
6. **片头片尾、口播**：有些视频开头有几十秒的讲话或广告，这个改不了。插件拿不到「正片从哪开始」的信息。
7. **封面**：16:9 的封面被裁成正方形，左右会被切掉，字幕条也可能被切掉一半。音乐榜的条目可以用专辑封面（若接口有），其他的保持居中裁剪。
8. **响度**：不同 UP 主的音量差别很大。B站的播放接口没有给出响度信息（实测 `volume` 字段为空），只能依赖 App 自带的音量均衡。
9. **看不了的视频**：失效、充电专属、付费、互动视频、番剧和电影（ep/ss 链接）。现在会报一个笼统的错误。改法：搜索和列表里直接标成不可播放（`unavailable`），粘贴番剧链接时明确提示「暂不支持番剧」。
10. **风控**：歌手页靠搜索，搜索请求多了更容易触发 B站的反机器人检查。歌手页结果缓存 10 分钟，失败时提示稍后再试，不重复请求。

## 四、建议的顺序

| 优先级 | 内容 | 性质 | 工作量 |
| --- | --- | --- | --- |
| **P0** | 排行换成新分区接口，音乐榜读对字段，统一 ID | 修 bug | 小 |
| **P1** | 标题解析出歌名和歌手（含歌手页），搜索优先音乐分区，首页和电台只要音乐 | 语义翻译，体验提升最大 | 中 |
| **P1** | LRCLIB 歌词 | 体验提升大，需要多一个网络权限 | 小 |
| **P2** | 「当作喜欢的收藏夹」设置，不可播放视频的标注，长视频标注 | 打磨 | 小 |
| 不做 | 弹幕、按时间轴切分合集、去片头 | 收益低或拿不到数据 | — |

P0 和 P1 做完可以发 v0.2.0。
